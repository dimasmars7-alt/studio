# Подключение облака

Клиент Supabase включён в приложении. Надпись «Локально» означает, что пользователь не вошёл в аккаунт либо ещё не перенёс проекты. Публикация файлов сайта сама по себе не переносит данные из браузера в облако.

## Что подготовлено

- миграция `supabase/migrations/202610090001_cloud_foundation.sql`;
- роли владельца, фотографа, директора и наблюдателя;
- RLS для организаций, проектов, сценариев, сцен, публикаций и согласований;
- закрытый bucket `project-media`;
- переходные снимки одной организации с проверкой версии;
- браузерный клиент Auth, REST и Storage;
- разделение текущего локального состояния по организациям.

## Как включить

1. Создать проект Supabase в европейском регионе.
2. В SQL Editor выполнить миграцию из `supabase/migrations`.
3. В Authentication создать первого пользователя-владельца или разрешить регистрацию только по приглашению.
4. Проверить Project URL и publishable key в `src/cloud-config.js`. В текущей версии клиент уже включён.
5. Не добавлять в сайт `service_role` key, пароль базы или секрет OpenAI.
6. Перед первой отправкой скачать JSON-экспорт локальных данных.

## Первая миграция данных

Для каждой локальной организации клиент вызывает `claim_organization`, затем сохраняет результат `organizationSnapshot` через `save_workspace_snapshot` с ожидаемой версией `0`. Повторная запись требует актуальную версию; несовпадение означает конфликт, который нельзя затирать автоматически.

В разделе «Аккаунт» пользователь создаёт профиль с именем, подтверждает email при необходимости, входит и нажимает «Перенести проекты в облако». Первая отправка создаёт членство владельца для его организаций. На втором устройстве пользователь входит в тот же аккаунт и выбирает «Восстановить из облака». До успешного переноса данные остаются только в браузере первого устройства.

## Публичная ссылка на проекты

После базовой схемы выполните в SQL Editor файл `supabase/migrations/202610190001_public_catalog.sql` и опубликуйте обновлённые файлы сайта. Владелец входит в аккаунт на устройстве, где находятся актуальные проекты, нажимает «Перенести проекты в облако», затем в личном кабинете организации выбирает «Публичная ссылка». Полученную ссылку можно открыть без входа, в том числе на телефоне.

Публичная страница показывает только название организации, названия и описания проектов, названия тем. Работы, сценарии, кадры, заметки, публикационные тексты и файлы остаются в закрытом снимке организации. После очередной синхронизации публичный каталог обновляется автоматически. Кнопка «Отключить ссылку» сразу прекращает просмотр по ранее выданному адресу.

Проверка перед передачей ссылки: откройте её в приватном окне, убедитесь, что видны ожидаемые проекты и темы, а закрытые материалы недоступны. Пока первый перенос с компьютера не завершён, открытая страница не сможет показать его локальные данные.

## Проверка доступа

Перед включением на публичном сайте нужны отдельные тестовые пользователи для каждой роли:

- владелец видит и изменяет всё;
- фотограф меняет контент, но не участников;
- директор читает контент, комментирует и согласовывает;
- наблюдатель только читает;
- пользователь другой организации не получает записи и файлы даже прямым REST-запросом.
