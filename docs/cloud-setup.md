# Подключение облака

Облачная основа уже находится в проекте, но по умолчанию выключена. Опубликованный сайт продолжает работать с локальными данными, пока не создан и не проверен проект Supabase.

## Что подготовлено

- миграция `supabase/migrations/202610090001_cloud_foundation.sql`;
- роли владельца, фотографа, директора и наблюдателя;
- RLS для организаций, проектов, сценариев, сцен, публикаций и согласований;
- закрытый bucket `project-media`;
- переходные снимки одной организации с проверкой версии;
- браузерный клиент Auth, REST и Storage;
- разделение текущего локального состояния по организациям.

## Как включить

1. Создать проект Supabase в европейском регионе.
2. В SQL Editor выполнить миграцию из `supabase/migrations`.
3. В Authentication создать первого пользователя-владельца или разрешить регистрацию только по приглашению.
4. В `src/cloud-config.js` указать Project URL и publishable key, затем установить `enabled: true`.
5. Не добавлять в сайт `service_role` key, пароль базы или секрет OpenAI.
6. Перед первой отправкой скачать JSON-экспорт локальных данных.

## Первая миграция данных

Для каждой локальной организации клиент вызывает `claim_organization`, затем сохраняет результат `organizationSnapshot` через `save_workspace_snapshot` с ожидаемой версией `0`. Повторная запись требует актуальную версию; несовпадение означает конфликт, который нельзя затирать автоматически.

После проверки снимков можно подключить вход и кнопку «Перенести данные в облако» в интерфейсе. Перенос нормализованных разделов выполняется по очереди: проекты и работы, темы, сцены, публикации, согласования, затем медиа.

## Проверка доступа

Перед включением на публичном сайте нужны отдельные тестовые пользователи для каждой роли:

- владелец видит и изменяет всё;
- фотограф меняет контент, но не участников;
- директор читает контент, комментирует и согласовывает;
- наблюдатель только читает;
- пользователь другой организации не получает записи и файлы даже прямым REST-запросом.
